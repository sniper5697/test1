# User Preferences

## 협업 방식
- 감독관이 먼저 충분히 질문해 작업 흐름을 완전히 이해한 뒤 위임을 시작한다.
- 사용자를 단순 전달자나 중계자로 쓰지 않는다.
- 사용자의 특별한 지시가 없으면 감독관이 작업 에이전트에게 직접 지시한다.

## 기획 및 제작 흐름
- 홈페이지 작성 전 질문 단계는 `$socrates` 스킬을 우선 사용한다.
- 웹페이지 실제 작성은 `stitch`를 사용한다.
- 각 웹페이지 구조와 프레임 정리는 `stitch` 결과를 바탕으로 `figma`를 사용한다.
- 설치/인증/연결 절차가 반복되는 도구는 재사용 가능한 Codex 스킬 형태로 정리하는 것을 선호한다.

## 디자인 선호
- 참고 무드는 `ElevenLabs`의 톤/레이아웃과 `셀바스AI`의 정보 배치다.
- 선호 요소: `유리질감`, `부드러운 모션`, 화려하지만 기술 중심의 인상
- 회피 요소: `블랙톤`, `템플릿 느낌`

## 제품/UX 선호
- 메인 CTA는 단일 `데모 보기` 버튼을 우선한다.
- 데모는 같은 페이지 내 섹션 이동 방식이 좋다.
- 모바일에서 `데모 보기` 경험을 가장 중요하게 본다.

## 품질 기대치
- CI/CD 자동화 포함
- TDD 기반 구현
- Playwright를 이용한 직접 디버깅과 E2E 검증

## 문서화 선호
- 중요한 운영 규칙과 결정은 `AGENTS.md`와 `.claude/memory/`에 남긴다.
- 작업일지는 템플릿 구조에 맞춰 `docs/worklog/`에 기록한다.
- 트러블슈팅 과정도 다음 세션에서 재사용 가능하도록 스킬의 `references/`나 메모리에 남기는 편을 선호한다.
